# Стандарт разработки HTML5-баннеров Myslo

Этот документ фиксирует рабочие требования проекта «Баннеры на myslo». Применять к новым баннерам, если в задании не указаны исключения.

## Назначение и Adfox
- Размещение: правый рекламный блок на десктопном myslo.ru через Яндекс Adfox.
- Спецификация: https://yandex.ru/support/adfox/ru/banners/specs/banner-html5
- Размер рекламного места при настройке в Adfox: 100% × 100%.
- Минимальная гарантированная область: 240 × 400 px. Максимальный размер определяется контейнером пользователя.
- Один HTML5-креатив должен корректно адаптироваться к вертикальным, квадратным, горизонтальным и переходным соотношениям сторон.
- Учитывать макросы клика Adfox (%banner.reference_mrc_user1%, %banner.target%) и требования к JavaScript (включая nonce, когда требуется спецификацией).
- Ресурсы для публикации локальные, без зависимости от CDN; соблюдать ограничения спецификации Adfox по файлам и архиву.
- Анимации должны быть цикличными, без заметных скачков и пустых участков. Учитывать prefers-reduced-motion.

## Обязательные проверки до публикации
- Базовые размеры: 198×529 (стресс-тест), 240×400, 400×400, 612×400.
- Дополнительные: 400×800, 612×200, 1250×750 и размеры непосредственно по обе стороны точек адаптивного перехода.
- Проверять в браузере реальные размеры iframe/контейнера, не только CSS-код.
- Не допускать наложения и обрезания текста, логотипов и кнопок, деформации графики, нечитабельных подписей, скачков при изменении размера и разрывов бесконечных лент.
- Проверять несколько фаз анимации, включая смену сообщений, проходы бликов и циклы вспышек.
- Не утверждать, что визуальная проверка выполнена, если её провести не удалось.
- Отдельно проверить, что ZIP распаковывается, содержит все файлы и загружается в Adfox; не объявлять загрузку проверенной до фактического теста.

## Страница согласования
- Для каждого проекта делать отдельный index.html со встроенными iframe живого баннера в размерах 198×529, 240×400, 400×400 и 612×400.
- Показывать реальные пропорции; при необходимости масштабировать предпросмотр, не меняя внутренние размеры iframe.
- На странице: название проекта, размеры, ссылка «Скачать ZIP для Adfox», ведущая на ./adfox.zip.
- Страница должна открываться в GitHub Pages без ошибок JavaScript и отсутствующих ресурсов.
- Не добавлять служебные пояснения для хостинга на публичную страницу согласования.

## GitHub и структура
- Репозиторий: https://github.com/allgerasimof/myslo
- Каждый баннер размещать в собственной независимой папке (например, /100/, /100-2/).
- Структура папки:
  - index.html — страница согласования;
  - banner/index.html — собственно баннер;
  - banner/assets/ и/или другие локальные ресурсы баннера;
  - adfox.zip — отдельный готовый архив для загрузки в Adfox.
- Внутри страницы iframe указывает на banner/index.html, ссылка скачивания — adfox.zip.
- Нельзя использовать общие ресурсы другого баннера через ../: всё необходимое должно находиться внутри папки текущего проекта.
- Главная страница репозитория — каталог со ссылками на проекты.
- Публиковать через GitHub Pages, предоставлять ссылку вида https://allgerasimof.github.io/myslo/<папка>/.
- До передачи ссылки проверить, что GitHub Pages обновился и страница работает.
- Не изменять и не удалять существующие проекты без отдельного запроса.

## Рабочий процесс
1. Получить референсы, исходные изображения, текст, URL перехода и ограничения.
2. Создать адаптивный баннер, при необходимости автономный HTML для локального согласования.
3. Проверить композицию, ресурсы, анимации и переходные форматы в браузере.
4. Собрать отдельный ZIP для Adfox.
5. Создать страницу согласования с четырьмя размерами и ссылкой на ZIP.
6. Загрузить все файлы в новую папку репозитория, обновить каталог.
7. Проверить публичную ссылку и скачать ZIP со страницы.
8. Сообщить заказчику ссылки на предпросмотр и архив, честно указав, что проверено.

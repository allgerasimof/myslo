# Стандарт разработки и приёмки HTML5-баннеров Myslo

Обязательные требования для новых и изменяемых баннеров проекта. Приоритет: точность исходного макета, качество графики, адаптивность, совместимость с Adfox и фактическая проверка в браузере. Если конкретное задание противоречит стандарту, уточнить исключение.

## Назначение и Adfox
- Размещение: правый рекламный блок на десктопном myslo.ru, Яндекс Adfox.
- Спецификация: https://yandex.ru/support/adfox/ru/banners/specs/banner-html5 — перед выпуском сверять актуальные требования.
- Размер рекламного места: 100% × 100%; гарантированная рабочая область от 240×400 px; дополнительно проверять стресс-формат 198×529.
- Один HTML5-креатив адаптируется к произвольным вертикальным, квадратным, горизонтальным и переходным пропорциям, а не только к четырём предпросмотрам.
- Учитывать макросы клика Adfox (%banner.reference_mrc_user1%, %banner.target%) и требования к JavaScript/nonce.
- Все ресурсы локальные, без CDN. Проверять разрешённые расширения, ограничения по весу, количеству файлов, структуре ZIP и способу клика.
- **WebP не помещать в ZIP для Adfox**: этот формат уже вызвал ошибку «Архив содержит неподдерживаемый тип файла». Для фотографического фона использовать JPG/JPEG, для прозрачной графики — PNG (либо иные форматы только после проверки актуальной спецификации).
- Анимации цикличны, без скачков, пустых участков; учитывать prefers-reduced-motion.

## Работа с исходным макетом и графикой
- При наличии утверждённого макета сначала разобрать его на смысловые слои: **чистый фон, логотип, надписи, кнопка, декоративные элементы**. Не подменять утверждённые изображения новыми сгенерированными композициями или примитивными силуэтами без согласования.
- Из исходного фона убрать старые тексты, логотипы, кнопки и их остатки, чтобы они не дублировались под HTML-элементами. Восстановить закрытые участки качественно, без заметных швов, прямоугольных заплат, артефактов и повторяющихся фрагментов.
- Сохранять узнаваемых спортсменов, световые эффекты, цветовую гамму, контраст и композиционный замысел оригинала. Не добавлять произвольные объекты. Для спортивной сотни: слева чистый плавный переход в синий без тумана; спортсмены и световой ореол — в правой части.
- При необходимости **расширять фон** за границы исходного изображения (outpainting/дорисовка), а не растягивать и не искажать его. Края должны естественно продолжать изображение; разрешение должно быть достаточным для широких размеров.
- Логотип выделять отдельно, сохранять точную форму, медали и надписи; **прозрачный фон без прямоугольной подложки**, чистые края, без деформации. Для спортивной сотни — именно фирменный логотип «Тульская спортивная сотня» с медалями, не обычное «100».
- Заголовки, цветные плашки и CTA по возможности реализовывать HTML/CSS, не оставлять в фоне. Шрифты подбирать максимально близко к оригиналу, без случайной замены на Impact или чрезмерно тяжёлый системный шрифт; при необходимости использовать локальные лицензированные шрифты.
- Цветная плашка конструктивно связана со своим текстом (общий блок/внутренняя подложка), а не позиционируется независимо: она не должна «уезжать» при изменении размеров. Кнопка и надписи полностью читаемы, без обрезания.
- Сгенерированное изображение с несколькими вариантами баннера — только **визуальный референс**, не доказательство работоспособности HTML5. Не выдавать мокап за реальный предпросмотр.

## Адаптация фона и композиции
- Фон должен покрывать **100% рекламной области без пустых полос** при любом поддерживаемом размере. При этом не искажать пропорции исходной графики.
- Важно: обычный background-size: cover неизбежно обрезает часть изображения при несовпадении пропорций. Нельзя обещать одновременно отсутствие любого кадрирования, полное заполнение и сохранение пропорций для одной фиксированной картинки. Использовать осмысленные стратегии: расширенный фон с безопасными зонами, отдельные варианты композиции/кадра для диапазонов пропорций, позиционирование смыслового центра, многослойные градиенты и декоративные продолжения.
- Критически важные объекты (лица/силуэты, кубок, медали, логотип, текст, CTA) не должны попадать под нежелательное кадрирование. Допустимо кадрировать только второстепенные участки фона; если необходимо — перестраивать композицию, а не масштабировать весь макет целиком.
- На узких форматах текст и кнопка должны занимать предусмотренные области, а спортсмены оставаться узнаваемыми; на широких — заполнять всю площадь без повторяющихся фрагментов и пустот.
- Проверять не только размеры с демонстрационной страницы, но и произвольные ширины/высоты и точки смены CSS-правил.

## Обязательная локальная проверка в браузере — блокирующий этап
**Не передавать готовую сборку и не объявлять баннер готовым без локальной браузерной проверки.**
- Открыть локальную страницу согласования и реальный `banner/index.html` в браузере (встроенный браузер Work, если доступен; либо локальный Chromium/Playwright или эквивалентный браузерный движок).
- Проверять именно HTML5-рендер в iframe/контейнере с реальными внутренними размерами, а не статические изображения и не только CSS-код.
- Минимальный набор размеров: **198×529, 240×400, 400×400, 612×400, 400×800, 612×200, 1250×750**, а также непосредственно до/после каждого breakpoint и несколько случайных промежуточных соотношений сторон.
- Сохранять/просматривать фактические скриншоты для всех ключевых размеров. Проверить визуально: нет обрезанного текста, наложений, деформации логотипа, отделившейся плашки, пустот фона, резких стыков, непредусмотренного кадрирования и ухудшения качества изображения.
- По возможности автоматически проверять размеры bounding boxes текста, CTA и логотипа, их выход за границы контейнера и пересечения; автоматические проверки **не заменяют** просмотра скриншотов.
- Проверить несколько моментов каждой анимации (в том числе вспышки, блики, бегущие ленты, смену сообщений), плавность цикла и режим reduced motion.
- Проверить отсутствие ошибок JS, отсутствующих ресурсов и неожиданных внешних запросов; протестировать изменение размеров контейнера без перезагрузки.
- Найденные проблемы исправить и **повторить** браузерные проверки до передачи результата.
- Если браузер недоступен, честно указать это и **не маркировать сборку как готовую/проверенную**. Сначала попытаться доступные локальные способы проверки; не заменять проверку сгенерированным мокапом.

## Проверка ZIP для Adfox
- ZIP содержит HTML в корне и все локальные ресурсы по корректным относительным путям. Не включать в Adfox-архив страницу согласования и посторонние исходники.
- Проверить распаковку, CRC/целостность, список расширений, относительные пути, вес файлов и отсутствие WebP; открыть **распакованный** баннер локально в браузере.
- Проверить обработку макросов Adfox и переход по клику в тестовом окружении.
- Не писать «Adfox принял архив», пока не было реальной успешной загрузки в Adfox. Успешная распаковка не равна совместимости с Adfox.

## Страница согласования
- В папке проекта `index.html` — страница с **живыми iframe** баннера в размерах 198×529, 240×400, 400×400 и 612×400.
- В предпросмотре сохранять реальные пропорции; масштабировать можно только внешнюю сцену, не менять внутренние размеры iframe.
- Показывать название проекта, размеры и ссылку «Скачать ZIP для Adfox» на `./adfox.zip`.
- При необходимости добавить расширенные стресс-тесты отдельно, не перегружая публичную страницу.
- Страница должна работать на GitHub Pages без JS-ошибок и отсутствующих ресурсов. Не добавлять служебные пояснения по хостингу.

## GitHub и структура
- Репозиторий: https://github.com/allgerasimof/myslo
- Каждый баннер — отдельная независимая папка (`/100/`, `/100-2/`, `/100sport/` и далее):
  - `index.html` — страница согласования;
  - `banner/index.html` — HTML5-креатив;
  - `banner/assets/` — его локальные ресурсы;
  - `adfox.zip` — отдельный готовый архив для Adfox.
- Не ссылаться на ресурсы соседних проектов через `../`. Внутри iframe использовать `banner/index.html`.
- Корневой `index.html` репозитория — каталог **всех** баннеров со ссылками на страницы согласования.
- Публикация: `https://allgerasimof.github.io/myslo/<папка>/`. После коммита проверить актуальность GitHub Pages, загрузку ресурсов, работу iframe и скачивание ZIP.
- Не менять другие проекты без отдельного запроса.

## Обязательный порядок работы
1. Получить исходники, утверждённый макет, тексты, ссылку перехода и ограничения.
2. Подготовить и проверить **чистый расширенный фон**, отдельно прозрачный оригинальный логотип и остальные ресурсы.
3. Собрать адаптивный HTML5-креатив с независимыми текстами/плашками/CTA.
4. **Локально открыть в настоящем браузере**, проверить все размеры и переходы, получить реальные скриншоты; исправить замечания и повторить тест.
5. Собрать ZIP для Adfox только из поддерживаемых ресурсов, проверить его содержимое и браузерный рендер распакованной версии.
6. Собрать страницу согласования с четырьмя живыми iframe и ссылкой на ZIP; проверить локально.
7. Загрузить в отдельную папку GitHub, обновить корневой каталог.
8. Проверить GitHub Pages и скачивание опубликованного ZIP.
9. Передать ссылки и краткий отчёт: **что визуально проверено, какие размеры проверены, что не проверено (в частности, фактическая загрузка в Adfox)**. Не утверждать о выполнении проверок без доказательств.
